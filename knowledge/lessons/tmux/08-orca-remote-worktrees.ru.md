Mac — не всегда лучшее место для работы агентов. Долгой сборке нужна машина побыстрее, иной задаче — GPU, а порой хочется, чтобы агенты продолжали трудиться, пока ноутбук спит. Для этого в Orca есть `SSH worktree` — worktree, который живёт на удалённом хосте, а управляется из Orca на вашем Mac.

## Что где выполняется

SSH worktree делит работу между двумя машинами:

- **Удалённый хост** хранит репозиторий и git worktree. Там же работают агенты, терминалы и команды git.
- **Orca на вашем Mac** показывает редактор, дифф и остальной интерфейс. Приложение владеет соединением и управляет хостом.

Orca синхронизирует файловые события через соединение, поэтому удалённый worktree ощущается как локальный: тот же редактор, тот же просмотр диффа, те же агенты. Меняется лишь машина, которая выполняет работу.

## Добавление SSH target

`SSH target` — это удалённый хост, сохранённый в Orca. Вам понадобится SSH-доступ к нему, а если вы работаете с репозиторием, то и git на этом хосте. Агент тоже запускается там, поэтому его CLI и вход в аккаунт должны быть на хосте, а не только на вашем Mac.

Чтобы добавить target:

1. Откройте в Orca **Settings → SSH**.
2. Нажмите **Add Target**.
3. Укажите хост, пользователя, порт и, при желании, файл ключа. Вместо этого можно открыть в том же диалоге выбор **OpenSSH config**: он ищет хосты в `~/.ssh/config` и заполняет форму по выбранному.
4. Нажмите **Test**, чтобы проверить соединение, а затем **Save**.

Если ключ защищён парольной фразой, Orca спросит её при первом подключении. Парольные фразы хранятся в памяти, пока приложение открыто.

Сохранённые target собираются в список в **Settings → SSH**. В каждой строке видны имя, адрес вида `user@host:port`, состояние соединения и кнопки вроде **Connect** и **Test**. Кнопка **Import** разом добавляет хосты из вашего OpenSSH config.

![Страница настроек SSH со списком из двух сохранённых target и кнопками Connect и Test. Над списком — кнопки Import и Add Target.](./orca-remote-worktrees/ssh-settings-targets.jpg)

Кроме того, Orca проверяет `host key` — ключ, которым сервер подтверждает, что он тот, за кого себя выдаёт. Хост, уже совпадающий с записью в файле `known_hosts`, подключается без лишних вопросов. По умолчанию новый хост Orca принимает при первом контакте и запоминает. Если же у знакомого хоста вдруг оказывается другой ключ, Orca отклоняет соединение ещё до того, как запросит пароль или парольную фразу. Прежде чем следовать шагам восстановления из сообщения об ошибке, сверьте новый отпечаток ключа.

## Создание удалённого worktree

Создайте worktree как обычно. В диалоге создания откройте **Run on** и выберите свой SSH target вместо локального Mac. Orca выполнит `git worktree add` на удалённом хосте.

В списке **Run on** перечислены готовые хосты. Там же появляются хосты, которые уже подключены, но ещё не знают о вашем проекте. Для такого хоста выберите **Set project location** прямо в этой форме, а затем укажите существующую копию репозитория на хосте или клонируйте его туда. Отключённый хост предложит **Connect** прямо в списке.

![Диалог Create worktree с раскрытым списком Run on. В нём Local Mac и удалённый хост openclaw, у каждого указан путь к проекту.](./orca-remote-worktrees/create-worktree-run-on.png)

Дальше всё идёт так же, как локально:

1. Запустите агента. Он работает на удалённом хосте, а не на ноутбуке.
2. Правьте файлы в редакторе Orca. Каждое сохранение Orca отправляет в удалённую файловую систему.
3. Просматривайте дифф, делайте коммит и push из Orca на вашем Mac.

Чтобы забрать что-то к себе, щёлкните правой кнопкой в файловом проводнике SSH worktree. Для файла выберите **Download**, для папки — **Download Folder**. Загрузка папки доступна, только если её поддерживает соединение.

## Как пережить обрыв связи

У удалённого worktree есть индикатор с текущим состоянием SSH: зелёный — подключено, жёлтый — идёт переподключение, красный — соединение потеряно. Когда хост отваливается, на карточке его рабочего пространства может появиться кнопка, позволяющая подключиться снова.

Обрыв связи не останавливает работающих агентов. Ноутбук уснул, Wi-Fi пропал — а агент продолжает трудиться на хосте. Orca переподключается, снова присоединяет терминал и воспроизводит пропущенный вывод. Состояния агентов — working, idle, blocked — доходят с удалённого хоста до сайдбара так же, как при локальной работе.

Всё это возможно благодаря `relay` — небольшому посреднику, который Orca устанавливает на удалённый хост при первом подключении. Relay владеет удалёнными терминальными сессиями, поэтому они продолжают жить, даже если закрыть Orca на Mac. Когда вы снова откроете приложение и подключитесь, терминалы вернутся в свои вкладки вместе с историей вывода.

Эта идея уже знакома вам по tmux и Herdr: там серверный процесс на удалённом хосте сохранял ваши оболочки между SSH-подключениями. В Orca ту же работу берёт на себя relay.

Удалённым терминалам нужен нативный модуль. На Linux-хосте relay может собирать его на месте, а для этого нужны `make`, компилятор C++ и `python3`. Без этих инструментов файлы, git и редактор работают, но терминалы не запускаются. Когда инструменты появятся на хосте, переподключитесь, чтобы relay завершил настройку.

## Проброс портов

Агент может запустить на удалённом хосте сервер разработки. Чтобы открыть его на Mac, используйте `проброс портов`: он делает удалённый порт доступным на ноутбуке.

Для удалённого worktree в правом сайдбаре есть вкладка **Ports**. Нажмите Cmd+Shift+I, чтобы её показать. В разделе **Detected** Orca перечисляет порты, которые слушают на удалённом хосте, и одним щелчком пробрасывает любой из них на ваш Mac. Пробросы можно также добавлять, менять и удалять вручную.

Пробросы сохраняются после перезапуска приложения и переподключения по SSH. Привилегированный удалённый порт, например 80, автоматически отображается на другой локальный порт — скажем, 10080.

Встроенный браузер Orca тоже может выходить в сеть хоста. В **Settings → Browser** параметр **Browse through SSH workspace hosts** направляет трафик браузера и DNS-запросы через SSH-хост каждого рабочего пространства. Выключите его, чтобы браузер ходил в сеть с вашего Mac.

## SSH worktree или Remote Orca Server

В Orca есть и другой удалённый режим — `Remote Orca Server`. В нём на другой машине работает вся среда выполнения Orca: проекты, worktree, терминалы и агенты принадлежат ей. Ваш Mac, браузер или приложение на телефоне подключаются к ней как клиенты. Этот режим пока в бета-версии.

| Вопрос | SSH worktree | Remote Orca Server |
| --- | --- | --- |
| Кто владеет средой выполнения | Orca на вашем Mac | Orca на удалённой машине |
| Что нужно удалённой машине | SSH-доступ, git и CLI агентов | Запущенное приложение Orca или `orca serve` |
| Кто может подключаться | Хостом управляет один ноутбук | Ноутбук, браузер, телефон и автоматизация делят одну среду |
| Обычная настройка | Добавить target и выбрать его в **Run on** | Создать ссылку доступа на сервере и вставить её в **Add Server** |

SSH worktree подходят, когда у вас уже есть сервер или машина для разработки и хочется запускать агентов там, не ставя второй экземпляр Orca. Remote Orca Server уместен, когда одна постоянно включённая машина должна хранить все сессии для нескольких клиентов. Режимы можно сочетать в одной установке: локальные worktree для быстрых правок и SSH-хост для тяжёлой работы.
