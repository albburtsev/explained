Herdr — это менеджер терминальных рабочих пространств, задуманный под работу с агентами для программирования. Как и tmux, он держит терминальные процессы в фоновой сессии, пока вы отсоединяетесь и подключаетесь снова. Поверх этого Herdr добавляет рабочие пространства на уровне проекта и статусы агентов, так что терминал, которому нужно ваше внимание, находится сразу, без обхода всех панелей по очереди.

## Запуск Herdr

Перейдите в каталог проекта и запустите Herdr там:

```sh
cd path/to/your-project
herdr
```

При первом запуске Herdr запускает фоновую сессию по умолчанию или подключается к ней. Если в этой сессии ещё нет рабочего пространства, Herdr создаёт его автоматически.

## Как устроен интерфейс

Herdr раскладывает терминалы по трём уровням:

- **Рабочее пространство** — контейнер верхнего уровня для одного репозитория, задачи или исследования.
- **Вкладка** — одна раскладка внутри рабочего пространства. Вкладки помогают развести разные виды работы: агентов, сервер разработки, тесты и логи.
- **Панель** — настоящий терминал, в котором работает оболочка, агент или другой процесс. Панель продолжает жить, когда клиент отсоединяется.

Эта иерархия напоминает сессии, окна и панели tmux, но Herdr — самостоятельный инструмент со своими клиентом и сервером. Терминалами и состоянием процессов владеет его фоновый сервер, а видимый терминальный интерфейс — лишь подключённый к нему клиент.

## Работа мышью

Herdr изначально рассчитан на мышь. Щёлкните по рабочему пространству, вкладке, панели или агенту, чтобы перевести на него фокус. Щелчок правой кнопкой открывает контекстное меню с действиями вроде создания вкладки или разделения панели. Перетаскивайте границу между панелями, чтобы изменить их размер, и выделяйте текст перетаскиванием, чтобы скопировать его.

В macOS, пока включён захват мыши, открывайте ссылку, которую обрабатывает Herdr, через Control-клик. Обычный Command-клик достаётся внешнему терминалу, если вы не воспользуетесь его механизмом обхода.

Простая раскладка проекта может выглядеть так:

- одно рабочее пространство для репозитория;
- вкладка `agents`, разделённая на две или больше панелей с агентами;
- вкладка `runtime` для сервера разработки и тестов;
- вкладка `review` для просмотра диффов и логов.

## Основные клавиши

Префикс по умолчанию у Herdr тот же, что у tmux: нажмите Control-B, отпустите и затем нажмите клавишу действия. В таблице `prefix` обозначает эту двухшаговую последовательность.

| Действие | Клавиши |
| --- | --- |
| Показать действующие сочетания | `prefix+?` |
| Создать вкладку | `prefix+c` |
| Разделить вправо | `prefix+v` |
| Разделить вниз | `prefix+minus` |
| Перевести фокус между панелями | `prefix+h/j/k/l` |
| Следующая или предыдущая вкладка | `prefix+n` / `prefix+p` |
| Открыть навигацию по рабочим пространствам | `prefix+w` |
| Создать рабочее пространство | `prefix+shift+n` |
| Развернуть панель в фокусе | `prefix+z` |
| Закрыть панель в фокусе | `prefix+x` |
| Отсоединить клиент | `prefix+q` |

Те же повседневные задачи с раскладкой и навигацией можно решать мышью, поэтому сочетания клавиш можно осваивать постепенно. В качестве живой справки используйте `prefix+?`: она отражает вашу текущую конфигурацию.

## Присмотр за ИИ-агентами для программирования

Запустите агента для программирования в обычной панели его собственной командой — например, `codex` или `claude`. Herdr распознаёт распространённых агентов и показывает их состояние в сайдбаре. Состояние поднимается от панелей к вкладкам и рабочим пространствам:

- `working` — агент занят делом;
- `blocked` — ему нужны ввод, одобрение или решение;
- `done` — он закончил, а вы ещё не посмотрели результат;
- `idle` — он ждёт или его завершённое состояние уже просмотрено.

На этом строится практичный параллельный процесс:

1. Выделите каждому репозиторию своё рабочее пространство.
2. Запускайте независимых агентов в отдельных панелях или вкладках, чтобы у каждого были свой терминал и свой контекст.
3. Выносите тесты, серверы и логи в другие панели, а не смешивайте их вывод с выводом агента.
4. Следите за сайдбаром вместо того, чтобы по очереди опрашивать каждого агента. Сначала загляните к агентам в состоянии `blocked`, затем просмотрите тех, что отмечены как `done`.
5. Отсоединяйтесь, когда работа может идти без присмотра, и позже снова подключайтесь к той же сессии.

Для поддерживаемых агентов автоматическое распознавание работает без дополнительной настройки. Необязательные интеграции Herdr могут передавать более подробные сведения о жизненном цикле и сессии; загляните на официальную страницу интеграции для своего агента и не рассчитывайте, что все агенты сообщают о состоянии одинаково.

## Работа на удалённом хосте

Что понадобится: SSH-доступ к удалённому хосту. Herdr поддерживает два способа удалённой работы; для способа, где сначала открывается SSH, Herdr уже должен быть доступен на этом хосте.

В духе tmux можно сначала открыть оболочку по SSH и запустить Herdr на удалённом хосте:

```sh
ssh workbox
herdr
```

В режиме тонкого клиента Herdr подключайтесь прямо из локального терминала:

```sh
herdr --remote workbox
```

Локальный клиент Herdr подключается по SSH, запускает удалённый сервер Herdr или подключается к нему и отрисовывает удалённое рабочее пространство у вас на машине. Полный SSH URL может содержать пользователя и порт:

```sh
herdr --remote ssh://you@server:2222
```

Если нужен изолированный набор рабочих пространств, панелей и агентов, используйте именованную удалённую сессию:

```sh
herdr --remote workbox --session agents
```

Запускайте агентов для программирования в удалённых панелях точно так же, как локально. Отсоединитесь через `prefix+q` — удалённый сервер и агенты продолжат работать. Повторив ту же команду `herdr --remote`, вы вернётесь к ним, поэтому долгая работа агентов переживёт и сон ноутбука, и закрытие терминала, и обрыв соединения.

## Отсоединение, возврат и остановка

Отсоединение убирает только видимый клиент. Нажмите `prefix+q` или закройте окно внешнего терминала — сервер Herdr сохранит панели и агентов работающими. Чтобы снова подключиться из другого терминала, выполните:

```sh
herdr
```

Закрытие панели — совсем другое дело: `prefix+x` останавливает терминал этой панели. Пользуйтесь этим, когда работа в панели закончена.

Чтобы завершить всю сессию по умолчанию и остановить все процессы в её панелях, выполните:

```sh
herdr server stop
```

Останавливайте сервер осознанно: в отличие от отсоединения, эта команда не оставляет агентов работать. Для большинства перерывов или смены окна терминала лучше отсоединиться и потом подключиться снова.
