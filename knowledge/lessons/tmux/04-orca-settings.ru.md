В прошлом уроке мы запустили агента с настройками Orca по умолчанию. Прежде чем браться за настоящую работу, стоит пройтись по трём группам настроек. GitHub позволяет Orca показывать пулл-реквесты, задачи и проверки. Настройки агентов определяют, какой агент запускается и сколько ему позволено делать, не спрашивая вас. Настройки рабочих пространств задают, где окажется каждый новый worktree и что в нём выполнится первым делом.

## Откройте настройки и найдите нужное

Нажмите `Cmd+,`, чтобы открыть Settings. Настройки разложены по разделам — **General**, **Integrations**, **Agents**, **Notifications** и другим. Запоминать, где что лежит, не обязательно: введите ключевое слово в поле поиска, например `branch` или `github`, и Orca покажет подходящие настройки.

Кроме того, у каждого проекта есть собственные настройки. Откройте меню **⋯** проекта в сайдбаре и выберите **Project Settings**. Эти настройки действуют только для этого репозитория.

## Подключите GitHub

Своего входа в GitHub у Orca нет. С GitHub приложение общается через `GitHub CLI` — команду `gh` на вашем Mac — и пользуется той учётной записью, под которой `gh` выполнил вход. Поэтому вам понадобится GitHub CLI, причём с выполненным входом.

Откройте **Settings → Integrations** и найдите карточку **GitHub Integration**. Она показывает одно из состояний:

- **Connected** — Orca может пользоваться `gh`, и пулл-реквесты, задачи и проверки работают.
- **Not authenticated** — `gh` установлен, но вход в нём не выполнен.
- **Not installed** — Orca не находит `gh`.

Чтобы исправить **Not authenticated**, выполните в терминале эту команду и следуйте её подсказкам:

```sh
gh auth login
```

Затем нажмите **Re-check** на карточке. Узнать, какую учётную запись использует `gh`, можно так:

```sh
gh auth status -h github.com
```

Если у вас несколько учётных записей GitHub, войдите в каждую через `gh`, а затем выберите нужную для проекта в поле **GitHub Account** его **Project Settings**. Другие сервисы — GitLab, Bitbucket, Linear и Jira — подключаются в том же разделе **Integrations**.

## Разберитесь с частыми ошибками GitHub

Если статус пулл-реквестов, проверки или задачи перестали обновляться, причина почти всегда во входе, правах доступа или лимитах API GitHub, а не в поломке самой панели. Orca выводит короткое сообщение; найдите его в таблице:

| Сообщение | Вероятная причина | С чего начать |
| --- | --- | --- |
| GitHub authentication is unavailable | В `gh` не выполнен вход, или срок действия токена истёк | Выполните `gh auth status -h github.com`, затем `gh auth login` |
| GitHub is rate-limiting requests | Часовая квота API GitHub исчерпана | Дождитесь сброса и остановите лишние скрипты с `gh` |
| GitHub did not allow access | У токена нет нужных scopes или у вас нет доступа к репозиторию | Войдите заново со scope `repo` и откройте пулл-реквест в браузере |
| Repository is unavailable | Указан неверный remote, репозиторий приватный или переименован | Выполните `git remote -v` и откройте репозиторий в браузере |
| GitHub CLI is unavailable | `gh` нет в PATH, который видит Orca | Убедитесь, что `gh` работает в обычном терминале, затем закройте Orca и откройте снова |

`Rate limit` — это часовой бюджет вызовов API GitHub для вашей учётной записи. Его делят все инструменты, работающие под ней: Orca, `gh` в ваших терминалах и агенты, которые вызывают `gh`. Остаток показан в **Settings → Git & Source Control → GitHub API Budget**. Эти цифры могут выглядеть благополучно, даже когда живые запросы уже не проходят. Если данные расходятся, верьте ошибке на панели пулл-реквеста.

Одну ошибку легко не заметить. Если ваш `~/.zshrc` экспортирует `GITHUB_TOKEN` или `GH_TOKEN`, `gh` возьмёт этот токен вместо вашего входа, и устаревший токен приведёт к путаным ошибкам входа и лимитов. Удалите строку с экспортом, откройте новый терминал и войдите заново:

```sh
gh auth logout -h github.com
gh auth login -h github.com
```

После повторного входа перезапустите Orca, чтобы приложение подхватило новые учётные данные.

## Выберите агентов

Orca может запустить в терминале любого CLI-агента. Многие из них — Claude Code, Codex, Cursor CLI, Gemini, GitHub Copilot CLI и другие — уже есть в списке агентов и запускаются в один клик. Установить CLI каждого агента и войти в него нужно самостоятельно и заранее; уже существующие входы Orca подхватывает сам, например из `~/.claude` и `~/.codex`.

Откройте **Settings → Agents**. Главное здесь:

- Список найденных агентов. Отключите тех, кем не пользуетесь, — тогда в меню запуска останутся только нужные.
- **Default Agent** — агент, который заранее выбран при создании worktree. Можно указать конкретного агента, **Auto** или **No agent (blank terminal)**. В поле **Agent** диалога создания тоже есть пункт **Set as default**.

### Решите, сколько позволено агенту

По умолчанию Orca запускает каждого поддерживаемого агента с флагом обхода разрешений — `permission-bypass flag`. С этим флагом агент выполняет команды, не спрашивая вас. Например, для Claude Code это `--dangerously-skip-permissions`, для Codex — `--dangerously-bypass-approvals-and-sandbox`, для Gemini — `--yolo`. Логика такая: worktree одноразов, а дифф вы всё равно просматриваете до слияния. Но, как уже говорилось в прошлом уроке, worktree — не песочница безопасности.

Переключатель **Agent Permissions** переводит всех агентов в один из двух режимов:

- **Yolo** сохраняет флаги обхода, и запросов становится меньше.
- **Manual** оставляет агентам их собственные запросы на подтверждение.

Чтобы изменить поведение только одного агента, разверните его строку в списке и отредактируйте поля **Arguments** или **Environment**. Кнопка **Reset** возвращает исходное значение. Как только у агента появляется собственное значение, общий переключатель **Agent Permissions** его больше не затрагивает.

Собственные файлы агентов Orca тоже уважает: читает конфигурацию `.claude/` и `.codex/` в репозитории, так что ваши хуки продолжают срабатывать, а `CLAUDE.md` и `AGENTS.md` оставляет нетронутыми.

### Переключайтесь между учётными записями агентов

Некоторые пользуются несколькими учётными записями Claude или Codex — скажем, личной и рабочей. Этот шаг необязателен. Сначала один раз войдите в каждую учётную запись из терминала. Затем откройте в Settings раздел **Codex Accounts** или **Claude Accounts**, добавьте учётные записи и дайте каждой понятное имя.

Чтобы переключиться, нажмите на индикатор использования агента в строке состояния и выберите учётную запись в меню. **System default** — это тот вход, которым пользуется обычная команда `codex` или `claude` вне Orca.

![Всплывающая панель Codex в строке состояния Orca показывает использование за сессию и за неделю. В меню учётной записи есть System default и вторая сохранённая учётная запись.](./orca-settings/codex-account-switcher.png)

Новые сессии запускаются с выбранной учётной записью. Уже работающие агенты сохраняют свою, пока вы их не перезапустите.

## Настройте рабочие пространства и worktree

Каждый worktree Orca создаёт как папку на диске. Глобальные настройки определяют, где появятся эти папки и как будут называться ветки:

- **Workspace Directory** в разделе **General** — корневая папка для всех worktree. По умолчанию это `~/orca/workspaces`.
- **Nest Workspaces** в разделе **General** помещает каждый worktree в папку с именем его репозитория. Настройка включена по умолчанию, поэтому путь выглядит как `~/orca/workspaces/<repository>/<workspace>`.
- **Branch Prefix** в разделе **Git & Source Control** добавляет префикс к именам новых веток. Варианты — **Git Username** (по умолчанию), **Custom** и **None**. При имени пользователя `jdoe` рабочее пространство `fix-login-race` получит ветку `jdoe/fix-login-race`.

Если оставить имя рабочего пространства пустым, Orca назовёт его в честь какого-нибудь морского обитателя. Включите **Auto-Rename Branch From Work** в разделе **Git & Source Control**, если хотите, чтобы Orca переименовывал такую ветку, когда агент возьмётся за работу.

### Задайте значения по умолчанию для проекта

В **Project Settings** проекта можно переопределить глобальные значения:

- **Default Worktree Base** — ветка или ref, от которой начинаются новые worktree. Orca берёт её из ветки по умолчанию, обычно это `origin/main`.
- **Worktree Location** переносит worktree этого проекта в другую папку.

### Запускайте скрипт настройки

Новый worktree — это чистый checkout: в нём нет зависимостей, кэшей сборки и локальных секретов из игнорируемых файлов. Это исправляет скрипт настройки — `setup script`. Orca запускает его в новом worktree сразу после создания.

Хранить скрипт настройки можно в двух местах. Локальный скрипт задаётся в **Project Settings → Setup Script** и остаётся только на вашем Mac. Общий скрипт живёт в файле `orca.yaml` в корне репозитория, и его получает каждый, кто клонирует репозиторий:

```yaml
scripts:
  setup: |
    pnpm install
```

В скрипте доступны три переменные окружения: `ORCA_ROOT_PATH` — основной checkout, `ORCA_WORKTREE_PATH` — новый worktree, `ORCA_WORKSPACE_NAME` — имя рабочего пространства. **Archive Script** устроен так же, но выполняется перед тем, как Orca архивирует worktree.

Настройка **When to Run Setup** определяет, как запускается скрипт:

- **Ask every time** — спрашивать перед каждым запуском.
- **Run by default** — запускать автоматически.
- **Skip by default** — запускать, только когда вы сами это выберете.

Чтобы в каждый новый worktree копировались игнорируемые файлы вроде `.env`, перечислите их в файле `.worktreeinclude` в корне репозитория:

```text
.env
.env.local
```

Каждый новый worktree получит собственную копию этих файлов. Работают только точные пути: шаблоны с подстановочными знаками пропускаются.

## Настройте уведомления

Orca может сообщить, когда агент закончил работу, так что следить за ним не обязательно. В **Settings → Notifications** оставьте включённым **Agent Task Complete** и нажмите **Send Test Notification**, чтобы убедиться, что macOS показывает уведомления Orca.

## Проверьте настройки

Перед следующим уроком пройдитесь по этому списку:

| Настройка | Где | Хорошее начальное значение |
| --- | --- | --- |
| GitHub Integration | Integrations | Connected |
| Default Agent | Agents | Агент, которым вы пользуетесь чаще всего |
| Agent Permissions | Agents | Yolo для одноразовых worktree, Manual, если нужны подтверждения |
| Workspace Directory | General | `~/orca/workspaces` |
| Branch Prefix | Git & Source Control | Git Username |
| Default Worktree Base | Project Settings | `origin/main` |
| Setup Script | Project Settings или `orca.yaml` | Команды, которые готовят ваш проект к работе |
| Agent Task Complete | Notifications | Включено |
