В этом уроке мы проведём одну задачу через стандартный рабочий цикл Orca: начнём с задачи (issue) на GitHub, а закончим смерженным пулл-реквестом. Шаги подходят для любого GitHub-репозитория, добавленного в Orca, — при условии, что GitHub подключён так, как описано в прошлом уроке.

Цикл состоит из шести этапов:

1. Выбрать задачу.
2. Создать для неё worktree и запустить агента.
3. Протестировать работу агента и провести ревью.
4. Сделать коммит, отправить ветку и открыть пулл-реквест.
5. Разобраться с проверками и комментариями ревью.
6. Слить пулл-реквест и прибраться.

## Выбор задачи

Щёлкните **Tasks** в левом сайдбаре. На странице Tasks собрана работа на GitHub по вашим проектам. Переключитесь на **Issues**, чтобы увидеть открытые задачи, и сузьте список через поле поиска.

Щёлкните по задаче, чтобы открыть её подробности: описание и комментарии можно прочитать прямо здесь, не уходя на github.com. Убедившись, что это нужная задача, нажмите **Start workspace from issue**. Кнопка **Start** в строке задачи делает то же самое.

![Подробности задачи GitHub открыты внутри Orca; кнопка Start workspace from issue — в правом верхнем углу.](./orca-issue-to-merged-pr/start-workspace-from-issue.png)

## Создание worktree и запуск агента

Orca открывает окно создания рабочего пространства. В нём уже стоят имя задачи и ссылка на неё. Выберите нужного агента в поле **Agent**, затем нажмите **Create worktree** или `Cmd+Enter`.

Orca создаёт новый git worktree в фоне. Имя ветки получается из имени рабочего пространства, которое Orca взяла из задачи. Когда рабочая копия готова, агент открывается в первой вкладке worktree.

Задача и служит агенту контекстом. Orca запускает его с промптом, в котором уже есть ссылка на задачу, так что агент сам прочитает её на GitHub. У некоторых агентов, например у Claude Code, промпт остаётся ждать в поле ввода: прочитайте его, добавьте нужные подробности и нажмите Return, чтобы отправить.

![Claude Code запускается в новом worktree, и ссылка на задачу GitHub уже набрана в его промпте.](./orca-issue-to-merged-pr/agent-prefilled-issue-prompt.png)

## Наблюдение за агентом

Сидеть во вкладке агента не нужно. Карточка worktree в сайдбаре показывает те же отметки статуса, что знакомы вам по уроку «Основы Orca». Когда агент переходит из работы в простой, Orca присылает уведомление.

Если появился янтарный вопросительный знак, агент ждёт вашего разрешения или ответа — откройте его вкладку и ответьте. В остальных случаях просто дайте агенту закончить.

## Проверка результата

Когда агент закончит, проверьте его работу сами. Агент пишет код быстро, но отвечать за то, что попадёт в основную ветку, всё равно вам.

Начните с тестов. Нажмите `Cmd+T`, чтобы открыть терминальную вкладку в том же worktree, и запустите там тесты проекта, например:

```sh
npm test
```

Берите ту команду, которую описывает ваш проект. Можно также запустить приложение и опробовать изменение вручную. Терминал работает в каталоге worktree, поэтому видит ровно те файлы, что оставил агент.

Тесты скажут, работает ли код, но не скажут, то ли это изменение, которое нужно. Чтобы понять это, проведите ревью диффа — короткий цикл, в котором вы и агент передаёте работу друг другу:

1. Прочитать дифф.
2. Оставить замечания к строкам, которые нужно изменить.
3. Отправить агенту все замечания одним пакетом.
4. Проверить исправленный вариант.
5. Мелочи доправить вручную.

### Чтение диффа

Нажмите `Cmd+Shift+G`, чтобы открыть **Source Control** в правом сайдбаре. Изменённые файлы в нём разложены по разделам — например, **Changes** и **Staged Changes**. Если агент уже закоммитил свою работу, загляните в раздел **Committed on Branch**. Щёлкните по файлу, чтобы увидеть его `дифф` — строки, которые агент добавил и удалил. Кнопка **View all** у раздела открывает все его файлы во вкладке как единый сводный дифф.

На панели инструментов видно, сколько файлов изменилось. Дерево файлов рядом с диффом позволяет сразу перейти к нужному файлу. Там же можно переключаться между раскладками **Side by Side** и **Inline** и включить перенос длинных строк. Клавиша `F7` переносит к следующему изменению, `Shift+F7` — к предыдущему.

Сначала поищите очевидные неприятности: неожиданные файлы, удалённый код, правки за пределами задачи. Затем читайте дифф по ханкам. `Ханк` — это один блок изменённых строк вместе с несколькими неизменёнными строками вокруг. К каждому ханку задайте три вопроса:

- Нужно ли это изменение?
- Минимально ли оно?
- Совпадает ли оно по стилю с остальным файлом?

### Замечания через Annotate AI Diff

`Annotate AI Diff` — способ Orca комментировать изменения агента. Замечания прикрепляются к строкам диффа, а потом уходят агенту. Переписывать в чат имена файлов и номера строк самому не придётся.

![Поле для замечания открыто у 21-й строки сводного диффа в Orca. В нём написано «Revert the design doc», а под ним кнопки Cancel и Add note.](./orca-issue-to-merged-pr/add-note.png)

Чтобы добавить замечание:

1. Наведите курсор на строку диффа. Рядом с номером строки появится **+**.
2. Нажмите на **+**. Чтобы прокомментировать несколько соседних строк, сначала протяните по ним выделение.
3. Напишите замечание в появившемся поле. Markdown здесь работает.
4. Сохраните его клавишей Enter или кнопкой **Add note**. `Shift+Enter` переносит строку, а Esc отменяет ввод.

Можно обойтись и клавиатурой: выделите строки в диффе и нажмите `Cmd+Shift+A` — это сочетание по умолчанию для команды **Add Review Note**. Замечание закреплено за своей строкой: если после правки дифф сдвинется, Orca переместит замечание вместе со строкой.

Пишите замечания полными предложениями: что именно не так и чего вы ждёте взамен.

```text
This retry loop never stops when the server returns 401. Stop after the first 401 and show the login error instead.
```

### Отправка замечаний одним пакетом

Прежде чем что-то отправлять, пройдите дифф целиком. Когда в диффе есть замечания, на панели инструментов появляется счётчик **AI notes** и кнопка **Send**.

Нажмите **Send**. Orca соберёт из всех замечаний один промпт, и у каждого сохранятся его файл и диапазон строк. Затем откроется меню **Send notes to** со списком агентов этого worktree. Выберите агента, который написал изменения, или запустите из того же меню нового. Как только промпт дойдёт до агента, Orca уберёт отправленные замечания из диффа.

Отправка пакетом важна. Если посылать замечания по одному, агент будет раз за разом менять направление. Целый пакет даёт ему полную картину, и он вносит одну согласованную правку.

У команды **Send Review Notes to Agent** по умолчанию нет сочетания клавиш. Чтобы отправлять замечания с клавиатуры, назначьте его в **Settings → Shortcuts**.

### Проверка исправлений

Дождитесь, пока агент закончит, снова откройте дифф и пройдитесь по каждому пункту из последнего пакета. В диффе замечаний уже нет, но промпт со всеми ними остался в терминале агента. Если нужно вспомнить, о чём вы просили, прокрутите терминал назад.

- Если исправление неверно или неполно, добавьте новое замечание и объясните, чего ещё не хватает.
- Если вы передумали насчёт замечания до отправки, удалите его кнопкой **Delete note**.
- Отправьте новые замечания и дождитесь следующего варианта.

Повторяйте цикл, пока дифф не станет чистым.

### Правка мелочей вручную

Иногда исправление быстрее набрать, чем объяснить: опечатку, неудачное имя, забытую отладочную строку. Вносите такие правки, пока агент простаивает, чтобы вы с ним не меняли один и тот же файл одновременно.

Откройте файл в редакторе Orca — например, нажмите `Cmd+P`, чтобы вызвать Quick Open, и наберите часть имени файла. Редактор здесь — Monaco, тот же, что в VS Code. Он сам сохраняет файл, когда вы уходите из редактора или ненадолго перестаёте печатать, так что отдельного шага сохранения нет.

Чтобы увидеть свою правку в виде диффа, не покидая файла, включите во вкладке редактора **Changes view mode**. В этом режиме рабочая копия файла сравнивается с последним коммитом.

## Коммит, отправка и пулл-реквест

Когда дифф чист, сделайте коммит из Source Control. Внизу панели есть одна главная кнопка. Её надпись меняется и всякий раз подсказывает следующий полезный шаг:

1. **Stage All** добавляет в коммит все изменённые файлы. Можно индексировать и файлы по одному.
2. Напишите сообщение коммита или нажмите **Generate commit message with AI**, чтобы получить черновик по проиндексированным изменениям. Затем нажмите **Commit** или `Cmd+Enter`, пока фокус находится в панели.
3. **Publish Branch** впервые отправляет новую ветку на GitHub. Дальнейшие отправки идут через **Push**.
4. **Create PR** открывает форму пулл-реквеста.

Pre-commit-хуки репозитория выполняются как обычно. Если хук упадёт, Orca покажет его вывод. Кнопка **Fix with AI** в подробностях ошибки передаёт проблему агенту. Агента просят только устранить неполадку, а не обойти хуки.

В форме пулл-реквеста проверьте базовую ветку, заголовок, описание и состояние **Draft**. **Generate pull request details with AI** напишет заголовок и описание по вашим коммитам. Поскольку worktree связан с задачей, в сгенерированном тексте может появиться строка вроде `Fixes #42`. GitHub закрывает задачу 42, когда пулл-реквест с такой строкой сливается в ветку по умолчанию.

Перечитайте текст и создайте пулл-реквест. Теперь карточка worktree в сайдбаре показывает связанный пулл-реквест и его статус.

## Проверки и комментарии ревью

Откройте панель **Checks** в правом сайдбаре; если сайдбар скрыт, нажмите `Cmd+L`. Панель показывает статус пулл-реквеста, его `проверки` и комментарии. Проверки — это автоматические задания, например workflow GitHub Actions, которые запускаются при каждой отправке. Пока панель открыта, Orca продолжает их обновлять.

Упавшая проверка GitHub Actions вдобавок отмечается красной плашкой на карточке worktree. Щёлкните по проверке, чтобы прочитать лог задания прямо в Orca. Чтобы поручить исправление агенту, нажмите **Fix** рядом с упавшими проверками: Orca передаст агенту их названия и ссылки.

Комментарии коллег к ревью появляются в той же панели, и на любой из них можно ответить прямо там. Чтобы разобраться с замечаниями с помощью ИИ, нажмите **Send unresolved PR comments** в разделе комментариев — Orca передаст эти комментарии агенту. Можно поставить в очередь для агента и только часть из них.

После каждого исправления повторяйте тот же круг: проверьте результат, сделайте коммит и нажмите **Push**. Пулл-реквест обновится, и проверки запустятся заново.

## Слияние пулл-реквеста

Для открытого пулл-реквеста панель Checks показывает зелёную кнопку слияния. Её надпись следует способу слияния, принятому в репозитории по умолчанию, например **Squash and merge**. Когда проверки пройдены и требования к ревью выполнены, нажмите её, чтобы слить пулл-реквест прямо из Orca.

Если кнопка неактивна, наведите на неё курсор — подсказка назовёт причину: незавершённые проверки, обязательное одобрение или конфликты. Можно и не ждать, а выбрать **Enable auto-merge**: тогда GitHub сам сольёт пулл-реквест, как только все требования будут выполнены. Этот вариант появляется, только если репозиторий разрешает auto-merge.

## Уборка worktree

После слияния worktree своё отслужил. Для смерженного пулл-реквеста панель Checks показывает кнопку **Delete Workspace**. Удалить worktree можно и иначе — щёлкнув по нему правой кнопкой в сайдбаре.

Orca попросит подтверждения, а затем удалит каталог worktree и его локальную ветку. Слитый код остаётся в ветке репозитория по умолчанию. Если в описании пулл-реквеста было ключевое слово закрытия вроде `Fixes #42`, GitHub к этому моменту уже закрыл задачу.
