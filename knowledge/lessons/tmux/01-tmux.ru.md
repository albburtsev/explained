tmux — это терминальный мультиплексор: он держит несколько оболочек и программ внутри одного терминала и может оставить их работать после того, как вы закроете терминальный клиент или отключитесь от него. Поэтому tmux удобен для долгих команд и для того, чтобы разложить несколько связанных задач по местам, не открывая множество окон терминала.

## Запуск именованной сессии

Создайте сессию с именем `work` и сразу войдите в неё:

```sh
tmux new-session -s work
```

Теперь весь терминал занимает **клиент** tmux. Он подключён к **сессии** `work`, в которой поначалу есть одно **окно** с одной **панелью**:

- Сессия — это устойчивое рабочее место, которое переживает отсоединение.
- Окно занимает всю площадь клиента и ведёт себя как вкладка.
- Панель — это отдельная терминальная область внутри окна, в которой работает оболочка или другая программа.

В строке состояния видны имя сессии и её окна. Всё, что вы набираете, попадает в активную панель текущего окна.

## Клавиша-префикс

Программы внутри панели получают обычные нажатия клавиш. Чтобы обратиться к самому tmux, сначала нажмите его **префикс** — по умолчанию это `Ctrl-b`, — отпустите его и только потом нажмите клавишу команды. Например, запись `C-b c` означает «`Ctrl-b`, а затем `c`»; это не одновременное нажатие.

Эти сочетания покрывают основную работу:

| Клавиши | Действие |
| --- | --- |
| `C-b c` | Создать новое окно |
| `C-b ,` | Переименовать текущее окно |
| `C-b n` / `C-b p` | Перейти к следующему / предыдущему окну |
| `C-b 0` … `C-b 9` | Выбрать окно по номеру |
| `C-b %` | Разделить активную панель на левую и правую |
| `C-b "` | Разделить активную панель на верхнюю и нижнюю |
| `C-b` + стрелка | Перейти к панели в этом направлении |
| `C-b q` | Ненадолго показать номера панелей; нажмите номер, чтобы выбрать панель |
| `C-b z` | Развернуть активную панель или вернуть её прежний размер |
| `C-b ?` | Открыть полный список сочетаний; нажмите `q`, чтобы выйти из него |

Попробуйте создать второе окно, разделить одно из окон на две панели и попереключаться между ними. Оболочки и программы принадлежат своим панелям: переход в другую панель или окно их не останавливает.

## Отсоединение и возврат

Отсоединение закрывает только соединение клиента. Сессия и все программы внутри неё продолжают работать. Нажмите:

```text
C-b d
```

Вернувшись в обычную оболочку, выведите список доступных сессий:

```sh
tmux list-sessions
```

Снова подключитесь к именованной сессии:

```sh
tmux attach-session -t work
```

Этот цикл отсоединения и повторного подключения — сердце работы с tmux: вы запускаете работу один раз, оставляете её идти и возвращаетесь к ней позже из другого терминала.

## Удалённая работа, которая не обрывается

Собственного транспорта для удалённой работы у tmux нет. Вместо этого вы подключаетесь к удалённому хосту по SSH и запускаете tmux уже там. Что понадобится: SSH-доступ к удалённому хосту, где tmux уже должен быть доступен.

Подключитесь и создайте сессию `remote-work` — или подключитесь к ней, если она уже существует:

```sh
ssh workbox
tmux new-session -A -s remote-work
```

Если SSH-соединение оборвётся, сервер tmux и программы продолжат работать на удалённом хосте. Подключитесь снова и выполните ту же команду `tmux new-session -A -s remote-work`, чтобы вернуться. Флаг `-A` позволяет одной командой и создавать сессию, и подключаться к ней, а `-s` задаёт имя сессии.

Это пригодится для удалённого редактора, сервера разработки, набора тестов или агента для программирования — всего, что должно пережить сбой сети. По возможности отсоединяйтесь через `C-b d`, прежде чем уйти, но и случайный разрыв SSH не завершит сессию.

## Осознанный выход

`exit` завершает оболочку в активной панели. По умолчанию вместе с последней панелью закрывается и её окно, а вместе с последним окном — вся сессия. Пользуйтесь этим, только когда действительно собираетесь закончить работу:

```sh
exit
```

Чтобы из обычной оболочки остановить всю именованную сессию вместе со всеми программами в её окнах и панелях, выполните:

```sh
tmux kill-session -t work
```

Нажимайте `C-b d`, когда работа должна продолжаться, и используйте `exit` или `kill-session`, когда её пора завершить. Это различие убережёт вас от случайной остановки долгого процесса.
