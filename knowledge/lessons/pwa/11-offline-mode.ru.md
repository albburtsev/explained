После прошлого урока Daily Quote уже открывается без сети — при условии, что все нужные файлы лежат в кеше. Остаются два пробела. Страница, которая ни разу не попадала в кеш, показывает собственную страницу ошибки браузера. А если `quotes.json` нет ни в сети, ни в кеше, приложение сообщает: «Could not load quotes.»

В этом уроке вы закроете оба пробела, научите приложение подсказывать пользователю, что сеть, по всей видимости, пропала, и проверите результат от начала до конца.

## Добавляем офлайн-страницу

`Офлайн-страница` (offline page) — это небольшая страница, которую сервис-воркер возвращает, когда пользователь открывает страницу, загрузить которую не удаётся. Вместо страницы ошибки браузера человек видит страницу вашего собственного приложения.

Создайте `offline.html` в корне проекта:

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Offline · Daily Quote</title>
  <link rel="stylesheet" href="/style.css">
</head>
<body>
  <header>
    <h1>Daily Quote</h1>
  </header>
  <main>
    <p>You are offline, and this page is not saved on your device.</p>
    <p><a href="/">Open the home page</a>. It works without a network.</p>
  </main>
</body>
</html>
```

Не усложняйте эту страницу. Она должна работать совсем без сети, поэтому опирается только на файлы, которые уже лежат в кеше, — в данном случае на `style.css`.

Сервис-воркер подставляет эту страницу вместо другой, так что в адресной строке остаётся URL, который открыл пользователь, например `/news.html`. Именно поэтому путь к таблице стилей начинается с `/`: относительный путь отсчитывался бы не от той папки.

Ссылка ведёт на главную страницу, потому что та закеширована заранее. Пользователь попадает не в тупик, а на работающую страницу.

## Кешируем её заранее в новой версии кеша

Офлайн-страница должна оказаться в кеше раньше, чем пропадёт сеть. Поэтому добавьте её в app shell в `sw.js` и дайте кешу новое имя:

```js
const CACHE_NAME = 'daily-quote-v3';
const OFFLINE_URL = '/offline.html';

const APP_SHELL = [
  '/',
  '/index.html',
  '/about.html',
  '/style.css',
  '/app.js',
  '/manifest.webmanifest',
  '/icons/icon-192.png',
  '/icons/icon-512.png',
  OFFLINE_URL,
];
```

Новое имя решает сразу две задачи. Во-первых, меняются байты `sw.js`, и браузер устанавливает новый сервис-воркер. Во-вторых, этот сервис-воркер заполняет чистый кеш свежими копиями всех файлов. Тем временем старый сервис-воркер продолжает обслуживать открытые страницы из старого кеша. Когда новый активируется, функция `deleteOldCaches` из урока 9 удаляет старый кеш. Обработчики `install` и `activate` менять не нужно.

## Отвечаем офлайн-страницей на неудачную навигацию

В уроке 8 вы видели, что запрос с `request.mode === 'navigate'` загружает HTML-страницу целиком. Офлайн-страницу должны получать только такие запросы. Неудачно загруженное изображение или скрипт не должны получать в ответ HTML-страницу.

С обработчиком `fetch` из урока 10 навигация попадает в `cacheFirst`. Если в кеше ничего не нашлось, `cacheFirst` вызывает `fetch()`. Без сети `fetch()` отклоняется, вслед за ним отклоняется и промис, переданный в `respondWith()`, — и браузер показывает свою страницу ошибки. Значит, эту ошибку нужно перехватить и ответить офлайн-страницей.

Замените обработчик `fetch` такой версией:

```js
self.addEventListener('fetch', (event) => {
  const { request } = event;
  const url = new URL(request.url);

  // Network only: other methods and other origins go to the browser.
  if (request.method !== 'GET' || url.origin !== self.location.origin) {
    return;
  }

  // Data: answer fast, refresh in the background, never fail.
  if (url.pathname === '/quotes.json') {
    event.respondWith(
      staleWhileRevalidate(event).catch(() => fallbackQuotes())
    );
    return;
  }

  // Pages: cache first, then the offline page.
  if (request.mode === 'navigate') {
    event.respondWith(
      cacheFirst(request).catch(() => caches.match(OFFLINE_URL))
    );
    return;
  }

  // Other static files: cache first.
  event.respondWith(cacheFirst(request));
});
```

`catch` срабатывает только тогда, когда отказывает сама сеть. Если сервер доступен, но страницы не существует, `fetch()` возвращает ответ `404`. Тогда пользователь видит страницу сервера «не найдено» — и это правильный ответ.

`caches.match(OFFLINE_URL)` не может промахнуться. Страница входит в app shell, а если предварительное кеширование не удалось, новый сервис-воркер вообще не устанавливается.

## Добавляем запасной ответ для quotes.json

`staleWhileRevalidate` отвечает из кеша, когда может. Если же в кеше ничего нет, а сеть недоступна, его промис отклоняется. Так бывает, когда браузер очистил кеш или когда первая загрузка `quotes.json` не удалась.

В таком случае сервис-воркер может собрать ответ сам. Добавьте этот код в `sw.js` под функциями стратегий:

```js
const FALLBACK_QUOTES = [
  {
    text: 'No network right now. Your quotes will be back soon.',
    author: 'Daily Quote',
  },
];

function fallbackQuotes() {
  return new Response(JSON.stringify(FALLBACK_QUOTES), {
    headers: { 'Content-Type': 'application/json' },
  });
}
```

Конструктор `Response` создаёт ответ из строки. По форме этот ответ совпадает с `quotes.json`, поэтому `app.js` менять не придётся: он разберёт список и покажет единственную цитату из него.

Запасной ответ никогда не попадает в кеш: `staleWhileRevalidate` сохраняет только ответы, пришедшие из сети. Как только сеть вернётся, следующий запрос снова получит настоящий список.

## Показываем состояние сети

Пользователь, который видит старые цитаты, должен понимать почему. Браузер даёт подсказку: `navigator.onLine` равно `false`, когда браузер знает, что подключения к сети нет. Когда значение меняется, на `window` срабатывают события `online` и `offline`.

Добавьте строку состояния в шапку `index.html`, сразу после элемента `<nav>`:

```html
<p id="connection" role="status"></p>
```

`role="status"` просит программы экранного доступа озвучивать изменения её текста.

Добавьте этот код в конец `app.js`:

```js
const connectionElement = document.querySelector('#connection');

function showConnection() {
  connectionElement.textContent = navigator.onLine
    ? 'Online'
    : 'Offline — showing saved data';
}

window.addEventListener('online', showConnection);
window.addEventListener('offline', showConnection);
showConnection();
```

Страница вызывает `showConnection` один раз при запуске, а затем после каждого изменения.

Относитесь к этому значению лишь как к подсказке. Браузеры определяют его по простым правилам: как правило, подключение к локальной сети уже считается онлайном, даже если у этой сети нет выхода в интернет. Поэтому `false` — довольно надёжный признак неполадок, а вот `true` вовсе не означает, что ваш сервер доступен. Никогда не отключайте функции приложения, полагаясь на `navigator.onLine`. Настоящая проверка — удался ли запрос, а этот случай сервис-воркер уже обрабатывает.

## Проверяем в DevTools

Запустите сервер из папки `daily-quote/` командой `npx http-server -c-1` и откройте `http://localhost:8080` в Chrome. Затем выполните следующие шаги:

1. Перезагрузите страницу, чтобы браузер обнаружил новый сервис-воркер. Активируйте его кнопкой **Reload** в уведомлении об обновлении из урока 6 или нажмите **skipWaiting** в разделе **Application > Service workers**.
2. Откройте **Application > Cache storage**. Там остался только `daily-quote-v3`, и в нём есть запись для `/offline.html`. Если список выглядит устаревшим, нажмите **Refresh**.
3. В разделе **Application > Service workers** отметьте флажок **Offline**. Строка состояния сменится на «Offline — showing saved data» без перезагрузки, потому что сработало событие `offline`.
4. Перезагрузите страницу. Страница и цитата по-прежнему на месте — обе из кеша.
5. Откройте `http://localhost:8080/news.html`. Эта страница ни разу не кешировалась, поэтому вы увидите офлайн-страницу. Перейдите по её ссылке, чтобы вернуться на главную.
6. Не выходя из офлайна, откройте **Cache storage**, выберите строку `/quotes.json` и удалите её. Перезагрузите главную страницу: на ней появится запасная цитата.
7. Снимите флажок **Offline** и перезагрузите страницу. Настоящие цитаты вернулись, а `/quotes.json` снова лежит в кеше.

Флажок **Offline** — это тот же переключатель, что и пункт **Offline** в меню ограничения скорости (throttling) на панели **Network**. Повторите шаги 3–7 оттуда: откройте панель **Network**, выберите **Offline** в меню ограничения скорости, а в конце — **No throttling**. Заодно панель Network покажет, какие запросы не удались, а какие обслужил сервис-воркер.

Эта эмуляция действует только во вкладке, где открыты DevTools. Стоит закрыть DevTools, и вкладка снова пользуется настоящей сетью.

## Проверяем установленное приложение без сети

DevTools проверяют вкладку. Настоящая же цель — установленное приложение из урока 3, запущенное, когда сети нет.

На Mac одного отключения Wi-Fi недостаточно. `http-server` работает на том же компьютере, и запросы к `localhost` по-прежнему до него доходят. Для вашего приложения «сети нет» означает «сервер недоступен». Поэтому отключите и то и другое:

1. Откройте установленное приложение Daily Quote, пока сервер работает, чтобы оно перешло на новый сервис-воркер. Если появится уведомление об обновлении, активируйте сервис-воркер через него.
2. Закройте приложение. В терминале остановите сервер сочетанием `Ctrl-C`.
3. Выключите Wi-Fi в Пункте управления. Если Mac подключён ещё и кабелем Ethernet, отсоедините его.
4. Откройте Daily Quote из Dock или через Spotlight.

Окно приложения откроется с главной страницей и цитатой. В строке состояния — «Offline — showing saved data». Нажмите **About**: эта страница тоже в кеше.

Теперь снова включите Wi-Fi, но сервер не запускайте. Перезагрузите приложение сочетанием `Cmd-R`. Строка состояния покажет «Online», хотя сервер по-прежнему недоступен, а приложение продолжает работать из кеша. Так ограничения `navigator.onLine` выглядят на практике.

Приложение Chrome делит сервис-воркер и кеши с самим Chrome, поэтому у него уже есть всё, что сохранила вкладка браузера. Веб-приложение Safari в Dock хранит данные сайта отдельно от Safari. Ему нужно загрузить собственную копию app shell, пока сервер работает, так что там шаг 1 особенно важен. Закончив, снова запустите сервер командой `npx http-server -c-1`.
