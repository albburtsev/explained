В прошлом уроке вы создали `sw.js` в корне папки `daily-quote/`. Пока браузер никак этот файл не использует: страница должна сама попросить браузер установить его. Этот шаг называется `регистрацией` (registration). В этом уроке вы зарегистрируете сервис-воркер, выясните, какими страницами он управляет, и разберётесь, почему первое посещение проходит иначе, чем последующие.

## Регистрация из `app.js`

Добавьте этот код в конец `app.js`:

```js
if ('serviceWorker' in navigator) {
  window.addEventListener('load', async () => {
    try {
      const registration = await navigator.serviceWorker.register('/sw.js');
      console.log('Service worker registered. Scope:', registration.scope);
    } catch (error) {
      console.error('Service worker registration failed:', error);
    }
  });
}
```

Первая строка — это `проверка поддержки` (feature detection). Объект `navigator.serviceWorker` существует только в браузерах, которые поддерживают сервис-воркеры, и только в безопасном контексте. Если его нет, приложение просто работает как обычный сайт. В этом и заключается «прогрессивность» PWA.

`navigator.serviceWorker.register()` принимает URL скрипта сервис-воркера. Браузер загружает скрипт и в фоне начинает его установку. Метод возвращает промис, поэтому код дожидается его через `await`.

Регистрация может не удаться: скрипт отвечает `404`, содержит синтаксическую ошибку или находится на другом origin, а сама страница может оказаться вне безопасного контекста. В любом из этих случаев промис отклоняется, и блок `catch` выводит причину в консоль.

## Регистрация после загрузки страницы

Событие `load` наступает, когда страница загрузила изображения, стили и скрипты. При первом посещении новый сервис-воркер скачивает свой скрипт и нередко заполняет кеш прямо во время установки. Эта работа отнимает у страницы сеть и процессор. Если дождаться `load`, страница успеет появиться первой.

На последующих посещениях такая задержка ничего не стоит. Браузер помнит регистрацию: когда вы снова открываете приложение, сервис-воркер запускается ещё до отправки запроса за страницей, и вызов `register()` лишь подтверждает то, что уже существует.

## Объект регистрации

Промис разрешается объектом `ServiceWorkerRegistration`. Он связывает один скрипт сервис-воркера с одной областью действия на вашем origin. Сейчас пригодятся несколько его свойств:

- `registration.scope` — абсолютный URL области действия, например `http://localhost:8080/`.
- `registration.active` — сервис-воркер, который работает сейчас, или `null`, пока он ещё устанавливается.
- `registration.installing` и `registration.waiting` хранят сервис-воркер, который только готовится стать активным. Эти состояния подробно разобраны в следующем уроке.

Повторный вызов `register()` с тем же скриптом и той же областью действия второй регистрации не создаёт: если ничего не изменилось, он возвращает существующую. Поэтому его можно спокойно вызывать при каждой загрузке страницы.

## Область действия: какими страницами управляет сервис-воркер

`Область действия` (scope) регистрации — это префикс URL. Сервис-воркер управляет только теми страницами, чей адрес начинается с этого префикса. Такие страницы называются его клиентами.

По умолчанию область действия — это каталог, в котором лежит скрипт. Для `/sw.js` это `/`, поэтому сервис-воркер может управлять любой страницей на `http://localhost:8080`:

| URL скрипта | Область действия по умолчанию | Управляет `/index.html`? | Управляет `/about.html`? |
| --- | --- | --- | --- |
| `/sw.js` | `/` | Да | Да |
| `/js/sw.js` | `/js/` | Нет | Нет |

Область действия определяет, какими страницами управляет сервис-воркер, но не ограничивает того, что он может загружать. Подконтрольная страница вправе запрашивать `style.css`, `quotes.json` или файл с другого сайта, и сервис-воркер увидит каждый из этих запросов. Как их перехватывать, покажет урок 8.

## Параметр `scope`

Второй аргумент `register()` принимает параметр `scope`. С его помощью область действия можно сделать уже, чем по умолчанию:

```js
navigator.serviceWorker.register('/sw.js', { scope: '/quotes/' });
```

Такой сервис-воркер управляет `/quotes/` и всеми страницами внутри него, но не `/index.html` и не `/about.html`. Daily Quote это не нужно: всё приложение должно работать без сети.

Сравнение идёт как обычная проверка строкового префикса, поэтому область действия для каталога стоит заканчивать символом `/`. Область `/quotes` совпала бы и с `/quotes.json`, и с `/quotes-archive.html`. Если странице подходят несколько регистраций, управляет ею та, у которой область действия длиннее.

Расширить область действия за пределы каталога скрипта по умолчанию нельзя. Такой вызов завершится ошибкой `SecurityError`:

```js
navigator.serviceWorker.register('/js/sw.js', { scope: '/' });
```

Разрешить его может сервер — заголовком ответа `Service-Worker-Allowed`, который он отдаёт вместе со скриптом. Заголовок задаёт самую широкую область действия, допустимую для этого скрипта:

```http
Service-Worker-Allowed: /
```

В этом курсе заголовок не понадобится. Он нужен в тех случаях, когда положить скрипт в желаемое место нельзя.

## Почему `sw.js` лежит в корне

Держать `sw.js` в корне проекта — самый простой способ охватить всё приложение:

- Область действия по умолчанию становится `/`, и сервис-воркер управляет `index.html`, `about.html` и любой страницей, которая появится позже.
- Не нужны ни параметр `scope`, ни заголовок `Service-Worker-Allowed`. Простому статическому серверу вроде `http-server` не требуется никакой дополнительной настройки.

Кладите скрипт сервис-воркера в корень, даже если остальные скрипты живут в отдельной папке вроде `js/`. Кроме того, скрипт должен находиться на вашем собственном origin: зарегистрировать сервис-воркер с CDN нельзя.

## Какой сервис-воркер управляет страницей

`navigator.serviceWorker.controller` — это сервис-воркер, который управляет текущей страницей, или `null`, если такого нет. Добавьте в конец `app.js` ещё одну строку, вне обработчика `load`:

```js
console.log('Controlled by:', navigator.serviceWorker?.controller?.scriptURL ?? null);
```

Операторы `?.` защищают эту строку от ошибки в браузере без поддержки сервис-воркеров.

Теперь проверьте:

1. Запустите сервер из папки `daily-quote/` командой `npx http-server -c-1`.
2. Откройте в Chrome новое окно в режиме инкогнито сочетанием `Cmd+Shift+N`, чтобы не осталось прежних регистраций. Перейдите на `http://localhost:8080`.
3. Откройте консоль сочетанием `Cmd+Option+J`. Вы увидите `Controlled by: null`, а затем `Service worker registered. Scope: http://localhost:8080/`.
4. Перезагрузите страницу сочетанием `Cmd+R`. Теперь в консоли будет `Controlled by: http://localhost:8080/sw.js`.
5. Откройте `http://localhost:8080/about.html`. Эта страница тоже под управлением сервис-воркера, потому что входит в область действия `/`.
6. Перезагрузите страницу сочетанием `Cmd+Shift+R`. Жёсткая перезагрузка обходит сервис-воркер, и страница снова показывает `Controlled by: null`.

## Почему первое посещение остаётся без управления

Браузер выбирает управляющий сервис-воркер один раз — в момент, когда начинает загружать страницу. При первом посещении регистрации ещё нет, и страница стартует без сервис-воркера. Такой она и остаётся до конца своей жизни, даже если мгновением позже сервис-воркер становится активным.

Это правило сохраняет поведение страницы цельным: страница, загруженная из сети, не начинает вдруг посреди работы получать ответы от сервис-воркера. Управляющий сервис-воркер достанется уже следующей навигации внутри области действия — перезагрузке или переходу по ссылке на `about.html`.

Взять под контроль уже открытые страницы сервис-воркер может методом `clients.claim()`. Этот метод относится к жизненному циклу сервис-воркера, которому посвящён следующий урок.
