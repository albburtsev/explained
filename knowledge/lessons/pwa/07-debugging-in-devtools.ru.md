Сервис-воркер трудно разглядеть. Он работает в фоне, может пережить страницу, а его старая версия способна сохранять контроль даже после того, как вы изменили код. Chrome DevTools показывает, что именно установил браузер, и позволяет этим управлять. В этом уроке вы исследуете приложение Daily Quote инструментами, которые пригодятся во всех следующих уроках.

## Панель Application

Запустите приложение из папки `daily-quote/`:

```sh
npx http-server -c-1
```

Откройте `http://localhost:8080` в Chrome и нажмите `Cmd+Option+I`, чтобы открыть DevTools. Перейдите на панель **Application**. Если её не видно, нажмите кнопку `>>` в строке вкладок панелей.

В левой боковой колонке `панели Application` (Application panel) собрано всё, что браузер хранит для этого origin. Для PWA важнее всего три пункта: **Manifest**, **Service workers** и **Storage**.

## Проверка манифеста

Выберите **Manifest**. DevTools читает файл, на который ссылается страница, и раскладывает его поля по разделам:

- **Identity** — имя приложения, короткое имя и описание.
- **Presentation** — стартовый URL, режим отображения, цвет темы и цвет фона.
- **Icons** — все иконки, которые Chrome удалось загрузить. Флажок **Show only the minimum safe area for maskable icons** обрезает каждую иконку до области, которая видна всегда.

Если что-то не так, появляется раздел **Installability** с описанием ошибки. Проверьте это прямо сейчас: в `manifest.webmanifest` замените `icons/icon-192.png` на несуществующий путь и перезагрузите страницу. Иконка пропадёт из раздела **Icons**, а ошибка подскажет, что именно не удалось. Верните правильный путь и снова перезагрузите страницу.

Если Chrome не предлагает установить приложение, первым делом загляните сюда. Эта панель показывает, что Chrome на самом деле нашёл в манифесте, а это не всегда совпадает с тем, что вы, как вам кажется, написали.

## Состояние сервис-воркера

Выберите **Service workers**. Каждая регистрация для этого origin представлена отдельной записью:

- **Source** — ссылка на `sw.js` и время, когда браузер получил эту версию.
- **Status** — номер версии и её состояние, например `activated and is running`.
- **Clients** — открытые страницы, которыми управляет этот воркер.

Рядом со статусом есть ссылка **stop**, а если воркер остановлен — **start**. Нажмите **stop**. Браузер завершит воркер, но страница продолжит работать. Когда воркер снова понадобится, например для следующего запроса, браузер запустит его заново. Поэтому никогда не храните важные данные в глобальных переменных `sw.js`: при остановке воркера они исчезают.

## Управление жизненным циклом во время разработки

Эта панель даёт прямой доступ к жизненному циклу, о котором шла речь в прошлом уроке.

Присвойте константе `VERSION` в `sw.js` новое значение и перезагрузите страницу. Chrome установит новую версию. Ваш воркер вызывает `self.skipWaiting()` только после того, как пользователь нажмёт Reload в баннере обновления. До тех пор новый воркер остаётся в статусе `waiting to activate`, а страницей по-прежнему управляет старый. Вместо баннера можно нажать ссылку **skipWaiting** рядом с ожидающим воркером — он активируется сразу.

Остальные элементы управления нужны для таких задач:

- **Update** просит браузер немедленно проверить, нет ли на сервере нового `sw.js`.
- **Unregister** удаляет регистрацию. Страница остаётся открытой, а при следующей загрузке `app.js` снова зарегистрирует воркер.
- **Update on reload** заново устанавливает воркер при каждой загрузке страницы, даже если `sw.js` не менялся, и пропускает фазу ожидания. Включайте этот режим, пока пишете воркер, и выключайте, когда хотите проверить настоящее поведение обновлений.
- **Bypass for network** отправляет все запросы прямо в сеть, минуя обработчик `fetch` воркера. Страница при этом по-прежнему считается контролируемой. Это выручает, когда закешированные файлы заслоняют ваши последние изменения.
- **Offline** отключает сеть для этой страницы и её воркера.

Отметьте **Offline** и перезагрузите страницу. Появится страница ошибки Chrome об отсутствии сети: воркер пока не отвечает на запросы. В следующих уроках вы это исправите. Закончив, снимите флажок **Offline**.

## Консоль воркера и точки останова

У сервис-воркера собственная глобальная область, отдельная от страницы. Тем не менее его сообщения `console.log()` появляются на панели **Console**, а справа источником указан `sw.js`.

Чтобы выполнить код внутри воркера, откройте меню контекста в верхней части Console. По умолчанию в нём выбрано `top`. Выберите пункт для `sw.js` — теперь выражения выполняются в области воркера:

```js
self.registration.scope
```

Результат — `'http://localhost:8080/'`, область действия по умолчанию для воркера по адресу `/sw.js`.

Чтобы приостановить воркер, откройте `sw.js` на панели **Sources** через `Cmd+P` и щёлкните номер строки — так ставится `точка останова` (breakpoint). Можно и вписать в код инструкцию `debugger`:

```js
self.addEventListener('install', (event) => {
  debugger;
  console.log(`${VERSION}: install`);
  event.waitUntil(prepare());
});
```

Сохраните файл и перезагрузите страницу. Изменение создаёт новую версию, и браузер её устанавливает. Если DevTools открыт, воркер остановится на этой строке во время `install`. Теперь можно смотреть значения переменных и выполнять обработчик по шагам. Закончив, уберите эту инструкцию.

Некоторые воркеры работают, когда ни одна страница не открыта, — например, когда приходит push-сообщение. На такой случай в Chrome есть две служебные страницы:

- `chrome://inspect/#service-workers` показывает запущенные воркеры. Ссылка **inspect** открывает для выбранного воркера отдельное окно DevTools.
- `chrome://serviceworker-internals` перечисляет все регистрации в браузере вместе с их состоянием и журналами. К тем же сведениям ведёт ссылка **See all registrations** внизу панели **Service workers**.

## Ответы сервис-воркера на панели Network

Откройте панель **Network** и перезагрузите страницу. Каждая строка здесь — один запрос.

Когда на запрос отвечает сам воркер, в столбце **Size** вместо числа байтов стоит `(ServiceWorker)`. Запросы, которые воркер отправляет по собственной инициативе, например чтобы наполнить кеш, отмечены значком шестерёнки перед именем. Выберите запрос и откройте вкладку **Timing**: там видно, сколько времени ушло на запуск воркера и на его ответ.

Пока во всех строках указан обычный размер: в `sw.js` ещё нет обработчика `fetch`. Отметку `(ServiceWorker)` вы увидите в следующих уроках.

## Чистый лист: Clear site data

Иногда нужно увидеть приложение глазами человека, который открывает его впервые. Выберите в боковой колонке **Storage** и нажмите **Clear site data**. Флажки под кнопкой перечисляют, что удалит DevTools. По умолчанию среди них есть регистрации сервис-воркеров и **Cache storage** — кеши, которые создаёт воркер.

После очистки перезагрузите страницу: браузер зарегистрирует и установит воркер с нуля.

В боковой колонке есть и пункт **Cache storage**, где видны все кеши и сохранённые в них ответы. Он понадобится в уроке о Cache Storage API.

Полный перечень инструментов приведён в разделе [Debug Progressive Web Apps](https://developer.chrome.com/docs/devtools/progressive-web-apps) документации Chrome DevTools.
