`Progressive Web App` (PWA, прогрессивное веб-приложение) — это сайт, который умеет вести себя как установленное приложение. Он написан на тех же HTML, CSS и JavaScript, что и любой другой сайт, у него по-прежнему есть URL, и работает он по-прежнему на браузерном движке. Меняется другое: как он запускается, где живёт на компьютере и что умеет делать без сети.

Слово «прогрессивное» здесь ключевое. Каждая возможность PWA — это дополнительный слой поверх уже работающего сайта. Браузер, который её поддерживает, ею воспользуется; браузер, который не поддерживает, всё равно покажет обычный сайт.

## Что PWA добавляет к сайту

Обычный сайт живёт во вкладке браузера. PWA, помимо этого, может:

- Получить собственный значок в Dock и находиться через поиск Spotlight.
- Открываться в отдельном окне, без адресной строки и вкладок браузера.
- Запускаться и показывать содержимое, когда сеть медленная или её нет вовсе.
- Показывать push-уведомления и бейдж на своём значке.

При этом приложение остаётся частью веба. Новую версию вы публикуете так же, как обновляете сайт: выкладываете файлы на сервер. Никакой проверки в магазине приложений, и одна кодовая база обслуживает все платформы.

## Три составляющие

PWA держится на трёх составляющих:

| Составляющая | Что она делает | Где о ней рассказано в курсе |
| --- | --- | --- |
| Безопасный контекст | Позволяет браузеру доверять странице настолько, чтобы открыть ей мощные API | В этом уроке |
| Манифест веб-приложения | Сообщает операционной системе, как установить и запустить приложение | В уроках 2–3 |
| Сервис-воркер | Стоит между страницей и сетью и отвечает на запросы | В уроках 4–12 |

`Безопасный контекст` (secure context) — это страница, которую браузер получил надёжным способом. На практике это страница, загруженная по HTTPS. Страницы с локальной машины тоже считаются безопасными: `http://localhost`, `http://127.0.0.1` и любой хост вида `*.localhost`. Сервис-воркеры, push-уведомления и многие другие API доступны только в безопасном контексте. Страница может сама проверить своё положение через `window.isSecureContext`.

`Манифест веб-приложения` (web app manifest) — небольшой JSON-файл, который страница подключает через `<link rel="manifest">`. В нём записаны имя приложения, значки, стартовый URL и режим отображения, например отдельное окно. Браузеры читают манифест, когда устанавливают приложение.

`Сервис-воркер` (service worker) — это JavaScript-файл, который браузер выполняет отдельно от ваших страниц. Он может перехватить любой запрос страницы и решить, чем на него ответить: ответом из сети, из кеша или запасной страницей. Именно так PWA работает без сети, управляет обновлениями и принимает push-сообщения.

Ни одну из этих составляющих не нужно устанавливать как отдельную технологию. Всё это стандартные возможности веб-платформы, и вы добавляете их к сайту по одной.

## PWA на macOS

На macOS прогрессивное веб-приложение можно установить из Chrome и из Safari.

В Chrome и других браузерах на Chromium, например в Edge, у сайта с подходящим манифестом в адресной строке появляется кнопка установки. Кроме того, в меню Chrome можно выбрать **Cast, save, and share** → **Install page as app…** — этот пункт работает для любой страницы. Манифест же нужен для того, чтобы Chrome сам предложил установку; он же задаёт имя и значки приложения.

В Safari 17 и новее на macOS Sonoma 14 и новее нужно выбрать **File** → **Add to Dock**. Это работает для любого сайта, с манифестом или без него. Сам Safari установку не предлагает — её начинает пользователь. Если манифест есть, Safari настраивает приложение по нему. Установленное приложение открывается в отдельном окне, получает копию cookie из Safari, а остальное хранилище держит отдельно от браузера. Оно поддерживает сервис-воркеры, push-уведомления и бейджи.

Firefox на macOS веб-приложения не устанавливает, и там PWA работает как обычный сайт.

Подробно установка учебного проекта в обоих браузерах разобрана в уроке 3.

## Создайте учебный проект

На протяжении курса вы соберёте одно небольшое приложение под названием **Daily Quote**. Оно загружает список цитат и показывает случайную. Писать его вы будете на чистом JavaScript, без фреймворков и без сборки. Каждый урок что-то к нему добавляет, и в конце оно станет устанавливаемым приложением, которое работает без сети и отправляет push-уведомления.

Создайте папку `daily-quote` с пятью файлами:

```text
daily-quote/
├── index.html
├── about.html
├── style.css
├── app.js
└── quotes.json
```

`index.html` — главная страница:

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Daily Quote</title>
  <link rel="stylesheet" href="/style.css">
</head>
<body>
  <header>
    <h1>Daily Quote</h1>
    <nav><a href="/">Home</a> · <a href="/about.html">About</a></nav>
  </header>
  <main>
    <blockquote id="quote">Loading…</blockquote>
    <p id="author"></p>
    <button id="next" type="button" disabled>Another quote</button>
  </main>
  <script src="/app.js"></script>
</body>
</html>
```

`about.html` — вторая страница. На ней в следующих уроках будет видно, как сервис-воркер обслуживает больше одной страницы:

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>About · Daily Quote</title>
  <link rel="stylesheet" href="/style.css">
</head>
<body>
  <header>
    <h1>Daily Quote</h1>
    <nav><a href="/">Home</a> · <a href="/about.html">About</a></nav>
  </header>
  <main>
    <p>Daily Quote shows a random quote about programming.</p>
    <p>It is the learning project of the PWA course.</p>
  </main>
</body>
</html>
```

`style.css` задаёт простую вёрстку:

```css
body {
  font-family: system-ui, sans-serif;
  line-height: 1.5;
  max-width: 40rem;
  margin: 0 auto;
  padding: 1rem;
}

blockquote {
  font-size: 1.5rem;
  margin: 2rem 0 0.5rem;
}

#author {
  color: #555;
}
```

В `quotes.json` лежат данные:

```json
[
  {
    "text": "Simplicity is prerequisite for reliability.",
    "author": "Edsger W. Dijkstra"
  },
  {
    "text": "Premature optimization is the root of all evil.",
    "author": "Donald Knuth"
  },
  {
    "text": "The best way to predict the future is to invent it.",
    "author": "Alan Kay"
  }
]
```

`app.js` загружает цитаты и показывает одну из них. Кнопка выбирает другую цитату и остаётся неактивной, пока данные не пришли:

```js
const quoteElement = document.querySelector('#quote');
const authorElement = document.querySelector('#author');
const nextButton = document.querySelector('#next');

let quotes = [];

function showRandomQuote() {
  const quote = quotes[Math.floor(Math.random() * quotes.length)];
  quoteElement.textContent = quote.text;
  authorElement.textContent = `— ${quote.author}`;
}

async function loadQuotes() {
  try {
    const response = await fetch('/quotes.json');
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }
    quotes = await response.json();
    showRandomQuote();
    nextButton.disabled = false;
  } catch (error) {
    quoteElement.textContent = 'Could not load quotes.';
    console.error(error);
  }
}

nextButton.addEventListener('click', showRandomQuote);
loadQuotes();
```

Страницы ссылаются на файлы по путям, которые начинаются с `/`, например `/app.js`. Такой путь всегда ведёт от корня сайта, поэтому одинаково работает с любой страницы.

## Запустите проект

Для локального веб-сервера понадобится Node.js v20+. Запустите его из папки `daily-quote`:

```sh
npx http-server -c-1
```

При первом запуске `npx` спросит разрешения скачать пакет `http-server` — согласитесь. Затем сервер перечислит адреса, на которых он слушает; порт по умолчанию — `8080`. Флаг `-c-1` отключает HTTP-кеширование, и браузер всегда получает свежие версии файлов. Позже это пригодится: думать придётся только о том кеше, которым управляет ваш сервис-воркер.

Откройте `http://localhost:8080` в Chrome. На странице должна появиться цитата. Нажмите **Another quote**, чтобы сменить её, и откройте **About**, чтобы проверить вторую страницу.

Теперь убедитесь, что страница работает в безопасном контексте. Откройте Chrome DevTools сочетанием `Cmd-Option-I`, перейдите на панель **Console** и выполните:

```js
window.isSecureContext
```

Результат — `true`, потому что страница загружена с `localhost`. Помните о двух ловушках:

- Сервер выводит ещё и адрес в вашей локальной сети, например `http://192.168.1.20:8080`. Это обычный HTTP на нелокальном хосте, а значит, не безопасный контекст, и сервис-воркеры там не заработают.
- Не открывайте `index.html` двойным щелчком. Тогда страница загрузится по URL вида `file://`: Chrome блокирует `fetch()` для локальных файлов, а сервис-воркеры работают только по HTTP и HTTPS.

Закончив, остановите сервер, нажав `Ctrl-C` в терминале.

Пока Daily Quote ещё не PWA. Он работает в безопасном контексте, но у него нет ни манифеста, ни сервис-воркера. Манифест появится в следующем уроке.
