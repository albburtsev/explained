`Агенты для программирования` работают быстро, но скорость ещё не означает, что агент и человек договорились об одном и том же результате. Требования, которые живут только в чате, постепенно расплываются по мере того, как растёт разговор. Реализация может начаться раньше, чем кто-то проверит важные решения. А логика, стоящая за готовым изменением, нередко исчезает вместе с сессией.

`OpenSpec` — инструмент `разработки на основе спецификаций`, рассчитанный на работу с агентами для программирования. Он хранит замысел изменения, требования к нему, технические решения и задачи по реализации в виде Markdown-файлов прямо в проекте. Эти файлы можно проверить до того, как написан код, уточнять по ходу работы и оставить в репозитории, когда всё готово.

## Какую задачу решает OpenSpec

Хорошему процессу разработки мало подробного промпта. Ему нужен общий ответ на четыре вопроса:

1. Зачем нужно это изменение?
2. Как должна вести себя система, когда оно будет готово?
3. Как изменение впишется в существующую кодовую базу?
4. Какая работа ещё осталась?

В OpenSpec эти ответы принимают форму `предложения` (proposal), `спецификаций`, необязательного `дизайна` и `списка задач`. Вместе эти файлы называются `артефактами планирования`. Агент составляет их и опирается на них в работе, а человек проверяет принятые решения и сам определяет, когда начинать реализацию.

Это разработка на основе спецификаций без жёсткого водопада. Артефакты делают текущее понимание задачи видимым, но их по-прежнему можно поправить, если исследование или реализация откроют что-то новое.

## Установка OpenSpec на macOS

Выберите один способ установки. Если поставить один и тот же интерфейс командной строки (`CLI`) через оба пакетных менеджера, в `PATH` могут оказаться две разные версии.

### Homebrew

Если вы управляете консольными инструментами через Homebrew, установите формулу OpenSpec:

```sh
brew install openspec
```

Homebrew сам позаботится о CLI и о его зависимости от Node.js.

### npm

Потребуется `Node.js v20.19+`.

Затем установите CLI глобально, чтобы команда `openspec` была доступна в любом проекте:

```sh
npm install -g @fission-ai/openspec@latest
```

## Проверка и инициализация

Убедитесь, что оболочка находит установленный CLI:

```sh
openspec --version
```

Перейдите в проект, где будете использовать OpenSpec, и запустите интерактивную инициализацию:

```sh
cd path/to/your-project
openspec init
```

Инициализатор спросит, какими агентами для программирования вы пользуетесь, и создаст подходящие файлы интеграции. Чтобы настроить Codex без интерактивного выбора, явно передайте его идентификатор инструмента:

```sh
openspec init --tools codex
```

Инициализация создаёт структуру OpenSpec на уровне проекта и устанавливает инструкции, которые учат выбранного агента следовать рабочему процессу. Отдельное приложение OpenSpec или фоновый сервис для этого не нужны.
