A `.proto` contract describes a service, but TypeScript cannot use it directly. A `code generator` reads the contract and writes TypeScript: message types, a client class for callers, and a service definition for the server. Both sides of the course project use the same generated file.

This lesson uses three tools:

- `@grpc/grpc-js`, the official gRPC library for Node.js. It sends and receives calls.
- `ts-proto`, a popular plugin that generates TypeScript code for `@grpc/grpc-js`.
- `buf`, a protobuf compiler. It reads `.proto` files and runs plugins such as `ts-proto`. It comes as an npm package, so the project does not need a global install.

## Set up the project

Work in the `inventory` project from the previous lesson. Switch the project to ES modules and add the packages:

```sh
npm pkg set type=module
npm install @grpc/grpc-js @bufbuild/protobuf
npm install --save-dev @bufbuild/buf ts-proto tsx typescript @types/node
```

`@bufbuild/protobuf` is a runtime package that the generated code imports to encode messages. `tsx` runs TypeScript files in Node.js without a build step. `typescript` and `@types/node` check types.

Next, tell `buf` what to generate. Create `buf.gen.yaml` in the project root:

```yaml
version: v2
inputs:
  - directory: proto
plugins:
  - local: protoc-gen-ts_proto
    out: src/gen
    opt:
      - outputServices=grpc-js
```

`inputs` points to the folder with `.proto` files. The plugin `protoc-gen-ts_proto` comes from the `ts-proto` package, and `out` is the folder for generated files. The option `outputServices=grpc-js` asks for client and server code that works with `@grpc/grpc-js`.

Create `tsconfig.json` so that `tsc` can check the project:

```json
{
  "compilerOptions": {
    "target": "es2023",
    "module": "nodenext",
    "strict": true,
    "noEmit": true,
    "skipLibCheck": true
  },
  "include": ["src"]
}
```

Finally, add two scripts and generate the code:

```sh
npm pkg set scripts.gen="buf generate" scripts.typecheck="tsc"
npm run gen
```

The command creates one file: `src/gen/inventory/v1/inventory.ts`. Its path follows the path of the `.proto` file inside `proto/`.

## Find the generated API

Open the generated file. It starts with the comment `Code generated by protoc-gen-ts_proto. DO NOT EDIT.` Never edit it by hand. When the contract changes, run `npm run gen` again. These are the parts you will use:

| Export | Who uses it | What it is |
| --- | --- | --- |
| `GetItemRequest`, `WatchItemsRequest`, `Item` | Both sides | A TypeScript interface for each message, plus an object with the same name that can `encode`, `decode`, and `create` messages. |
| `InventoryServiceClient` | Client | A class with one method for each RPC. You create it with a server address. |
| `InventoryServiceServer` | Server | An interface that the service implementation must satisfy. |
| `InventoryServiceService` | Server | A service definition: the method paths and functions that convert messages to bytes. The server registers the implementation with it. |

Here are the key types, shortened from the generated file:

```ts
export interface Item {
  sku: string;
  name: string;
  category: string;
  quantity: number;
}

export interface InventoryServiceServer extends UntypedServiceImplementation {
  getItem: handleUnaryCall<GetItemRequest, Item>;
  watchItems: handleServerStreamingCall<WatchItemsRequest, Item>;
}

export interface InventoryServiceClient extends Client {
  getItem(request: GetItemRequest, callback: (error: ServiceError | null, response: Item) => void): ClientUnaryCall;
  watchItems(request: WatchItemsRequest, options?: Partial<CallOptions>): ClientReadableStream<Item>;
  // ...more overloads that also accept metadata and call options
}
```

Protobuf names become TypeScript names: the RPC `GetItem` becomes the method `getItem`, and `int32` becomes `number`. The client's `getItem` reports its result through a callback. The client's `watchItems` returns a stream that you read item by item. On the server side, `handleUnaryCall` and `handleServerStreamingCall` are function types from `@grpc/grpc-js`; the next lesson implements them.

You may also see `@grpc/proto-loader` in other projects and in the official gRPC examples for Node.js. It loads the `.proto` file at runtime instead of generating code ahead of time. It works with the same `@grpc/grpc-js` library, but it gives you weaker types out of the box.

## Practice

1. Run all the setup commands above, then run `npm run gen` and `npm run typecheck`. The type check prints nothing after the script header when the project is correct.

2. In `src/gen/inventory/v1/inventory.ts`, find the TypeScript type of `Item.quantity` and the `path` of the `getItem` method. The answers are `number` and `/inventory.v1.InventoryService/GetItem`. gRPC sends this path over HTTP/2 to name the method it calls.

3. Add the field `string description = 5;` to `Item` in the contract and run `npm run gen`. Find `description: string` in the `Item` interface. Then delete the field and regenerate, so that your contract matches the course again. Nobody uses this field yet, so you can delete it without `reserved`.
