Контракт `.proto` описывает сервис, но напрямую воспользоваться им из TypeScript нельзя. `Генератор кода` (code generator) читает контракт и пишет TypeScript: типы сообщений, класс клиента для вызывающей стороны и определение сервиса для сервера. Обе стороны проекта курса работают с одним и тем же сгенерированным файлом.

В этом уроке понадобятся три инструмента:

- `@grpc/grpc-js` — официальная библиотека gRPC для Node.js. Она отправляет и принимает вызовы.
- `ts-proto` — популярный плагин, который генерирует TypeScript-код для `@grpc/grpc-js`.
- `buf` — компилятор protobuf. Он читает файлы `.proto` и запускает плагины вроде `ts-proto`. Его распространяют как npm-пакет, так что глобально устанавливать ничего не нужно.

## Настраиваем проект

Работайте в проекте `inventory` из предыдущего урока. Переключите проект на ES-модули и добавьте пакеты:

```sh
npm pkg set type=module
npm install @grpc/grpc-js @bufbuild/protobuf
npm install --save-dev @bufbuild/buf ts-proto tsx typescript @types/node
```

`@bufbuild/protobuf` — пакет времени выполнения, который сгенерированный код импортирует, чтобы кодировать сообщения. `tsx` запускает файлы TypeScript в Node.js без шага сборки. `typescript` и `@types/node` нужны для проверки типов.

Теперь объясните `buf`, что генерировать. Создайте в корне проекта `buf.gen.yaml`:

```yaml
version: v2
inputs:
  - directory: proto
plugins:
  - local: protoc-gen-ts_proto
    out: src/gen
    opt:
      - outputServices=grpc-js
```

`inputs` указывает на каталог с файлами `.proto`. Плагин `protoc-gen-ts_proto` входит в пакет `ts-proto`, а `out` — каталог для сгенерированных файлов. Опция `outputServices=grpc-js` просит сгенерировать код клиента и сервера, совместимый с `@grpc/grpc-js`.

Создайте `tsconfig.json`, чтобы `tsc` мог проверять проект:

```json
{
  "compilerOptions": {
    "target": "es2023",
    "module": "nodenext",
    "strict": true,
    "noEmit": true,
    "skipLibCheck": true
  },
  "include": ["src"]
}
```

Наконец, добавьте два скрипта и сгенерируйте код:

```sh
npm pkg set scripts.gen="buf generate" scripts.typecheck="tsc"
npm run gen
```

Команда создаёт один файл — `src/gen/inventory/v1/inventory.ts`. Его путь повторяет путь файла `.proto` внутри `proto/`.

## Находим сгенерированный API

Откройте сгенерированный файл. Он начинается с комментария `Code generated by protoc-gen-ts_proto. DO NOT EDIT.` Никогда не правьте его вручную: когда контракт меняется, снова запускайте `npm run gen`. Вот части, с которыми вы будете работать:

| Экспорт | Кто пользуется | Что это |
| --- | --- | --- |
| `GetItemRequest`, `WatchItemsRequest`, `Item` | Обе стороны | Интерфейс TypeScript для каждого сообщения, а также одноимённый объект, который умеет кодировать (`encode`), декодировать (`decode`) и создавать (`create`) сообщения. |
| `InventoryServiceClient` | Клиент | Класс, в котором на каждый RPC приходится по одному методу. Создаётся с адресом сервера. |
| `InventoryServiceServer` | Сервер | Интерфейс, которому должна соответствовать реализация сервиса. |
| `InventoryServiceService` | Сервер | Определение сервиса: пути методов и функции, которые превращают сообщения в байты и обратно. Сервер регистрирует реализацию именно через него. |

Вот ключевые типы — в сокращённом виде из сгенерированного файла:

```ts
export interface Item {
  sku: string;
  name: string;
  category: string;
  quantity: number;
}

export interface InventoryServiceServer extends UntypedServiceImplementation {
  getItem: handleUnaryCall<GetItemRequest, Item>;
  watchItems: handleServerStreamingCall<WatchItemsRequest, Item>;
}

export interface InventoryServiceClient extends Client {
  getItem(request: GetItemRequest, callback: (error: ServiceError | null, response: Item) => void): ClientUnaryCall;
  watchItems(request: WatchItemsRequest, options?: Partial<CallOptions>): ClientReadableStream<Item>;
  // ...more overloads that also accept metadata and call options
}
```

Имена из protobuf становятся именами TypeScript: RPC `GetItem` превращается в метод `getItem`, а `int32` — в `number`. Клиентский `getItem` сообщает результат через callback, а клиентский `watchItems` возвращает поток, который читают по одному товару. На стороне сервера `handleUnaryCall` и `handleServerStreamingCall` — это типы функций из `@grpc/grpc-js`; их реализацией займётся следующий урок.

В других проектах и в официальных примерах gRPC для Node.js вам может встретиться `@grpc/proto-loader`. Он загружает файл `.proto` во время выполнения, а не генерирует код заранее. Он работает с той же библиотекой `@grpc/grpc-js`, но без дополнительной настройки даёт более слабую типизацию.

## Практика

1. Выполните все команды настройки, затем запустите `npm run gen` и `npm run typecheck`. Если проект в порядке, проверка типов после заголовка скрипта ничего не выводит.

2. Найдите в `src/gen/inventory/v1/inventory.ts` тип TypeScript для `Item.quantity` и `path` метода `getItem`. Ответы: `number` и `/inventory.v1.InventoryService/GetItem`. Именно этот путь gRPC передаёт по HTTP/2, чтобы указать вызываемый метод.

3. Добавьте в `Item` поле `string description = 5;` и запустите `npm run gen`. Найдите `description: string` в интерфейсе `Item`. Затем удалите поле и сгенерируйте код заново, чтобы контракт снова совпадал с курсом. Этим полем ещё никто не пользуется, поэтому его можно удалить без `reserved`.
